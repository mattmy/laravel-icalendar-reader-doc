# 效能與安全

## 效能特性

- 從串流讀取時，完整行事曆也會留在記憶體中。預留比 `.ics` 檔案大小更多的記憶體。
- 處理大型行事曆時，盡量重用查詢與 `rawComponent()` 的結果，只產生需要的輸出格式。
- 每次呼叫 `occurrencesBetween()` 都會重新展開。將 `$until` 設在需求允許的最早時間。
  候選上限請見[重複事件查詢指南](/zh-TW/guide/calendars-and-events)。

用實際會匯入的大型行事曆測試，再決定 `max_bytes` 和執行程序的資源上限。也要預留
同時處理多個請求所需的記憶體。大型匯入可交給佇列，並為工作程序設定記憶體與時間限制。

## 安全

- 匯入前先驗證上傳檔案，並確認使用者有匯入權限。
- `fromPath()` 只應接收應用程式信任的本機路徑。套件不會下載 URL。
- 用戶端提供的 MIME 與檔名不可信，應以讀取結果或例外判斷內容是否合法。
- 顯示行事曆文字前先跳脫，開啟連結前先驗證。未知屬性與參數也要做同樣處理。
  行事曆可能包含個人資料，應避免記錄完整內容。
- 除了 `max_bytes`，也應設定網頁伺服器的上傳上限、請求逾時、頻率限制和程序記憶體上限。
